# Tích Hợp Deep Link Trên iOS & Android

<Info>
**Bạn sẽ học**: Cách khai báo Universal Link / App Link, xử lý link khi app đã cài (immediate), và khôi phục link trong lần mở đầu tiên khi app chưa cài (deferred). Mọi lời gọi mạng đều tới `POST /api/v1/track/open`.

Ví dụ dùng **SwiftUI (Swift)** và **Jetpack Compose (Kotlin)**; bạn có thể chuyển các đoạn entry-point sang UIKit / View truyền thống tương ứng.
</Info>

<Tabs>
  <Tab title="iOS (Swift)" icon="apple">
    ### 1. Khai báo Associated Domains

    Thêm domain Li2 của bạn vào file `.entitlements`:

    ```xml
    <key>com.apple.developer.associated-domains</key>
    <array>
        <string>applinks:your-domain.com</string>
    </array>
    ```

    Domain này phải trùng với domain đã cấu hình trên dashboard và file AASA mà Li2 phục vụ.

    ### 2. Định nghĩa model & lời gọi API dùng chung

    Cả luồng immediate lẫn deferred đều gọi cùng một endpoint với cùng một cặp model. Định nghĩa một lần rồi tái sử dụng:

    ```swift
    struct TrackOpenRequest: Encodable {
        var deepLink: String? = nil
        var li2Domains: [String]? = nil
        var clipboardStatus: String? = nil   // "read" | "empty" | "denied" | "optout"
        var installReferrer: String? = nil   // chỉ dùng cho Android
    }

    struct TrackOpenResponse: Decodable {
        struct Link: Decodable {
            let id: String
            let domain: String
            let key: String
            let url: String
        }
        let clickId: String
        let link: Link?          // nil khi deferred không đối chiếu được
        let matchMethod: String?
        let missReason: String?
        let platform: String?
    }

    // baseURL PHẢI gồm /api/v1, ví dụ "https://api.li2.ai/api/v1"
    func trackOpen(_ body: TrackOpenRequest) async throws -> TrackOpenResponse {
        var req = URLRequest(url: URL(string: "\(baseURL)/track/open")!)
        req.httpMethod = "POST"
        req.setValue("application/json", forHTTPHeaderField: "Content-Type")
        req.setValue(publishableKey, forHTTPHeaderField: "X-Li2-Key")  // li2_pk_...
        req.httpBody = try JSONEncoder().encode(body)

        let (data, _) = try await URLSession.shared.data(for: req)
        return try JSONDecoder().decode(TrackOpenResponse.self, from: data)
    }

    // Điều hướng theo phản hồi: khớp → mở đúng màn hình; trượt → fallback + lý do
    @MainActor
    func route(_ res: TrackOpenResponse) {
        if let dest = res.link?.url {
            router.open(dest)
        } else {
            router.showFallbackBanner(missReason: res.missReason)
        }
    }
    ```

    ### 3. Xử lý Universal Link (app đã cài — immediate)

    Trong entry point SwiftUI:

    ```swift
    WindowGroup {
        ContentView()
            .onOpenURL { url in
                store.handleIncomingURL(url)
            }
            .onContinueUserActivity(NSUserActivityTypeBrowsingWeb) { activity in
                guard let url = activity.webpageURL else { return }
                store.handleIncomingURL(url)
            }
    }
    ```

    `handleIncomingURL` chỉ gửi `deepLink` — đây là luồng immediate, **không** kèm `clipboardStatus`:

    ```swift
    func handleIncomingURL(_ url: URL) {
        hasReceivedUniversalLink = true   // chặn luồng deferred ở bước 4
        Task {
            let res = try await trackOpen(.init(deepLink: url.absoluteString))
            await route(res)
        }
    }
    ```

    ### 4. Khôi phục deferred trong lần mở đầu tiên

    Sau một khoảng chờ nhỏ (≈250ms để Universal Link kịp tới nếu có) và chỉ **một lần duy nhất** mỗi lần cài (cờ `firstLaunchRan`), hiển thị màn hình xin đồng ý rồi đọc clipboard. Mỗi nhánh map thẳng vào `TrackOpenRequest`:

    ```swift
    func recoverDeferredOnce() {
        guard !firstLaunchRan, !hasReceivedUniversalLink else { return }
        firstLaunchRan = true

        let body: TrackOpenRequest
        switch clipboardOutcome {       // kết quả sau khi người dùng tương tác PasteControl
        case .read(let copied) where copied.contains("li2_cid"):
            body = .init(deepLink: copied, clipboardStatus: "read")
        case .read:                                   // có nội dung nhưng không phải link Li2
            body = .init(li2Domains: ["your-domain.com"], clipboardStatus: "read")
        case .empty:
            body = .init(li2Domains: ["your-domain.com"], clipboardStatus: "empty")
        case .denied:                                 // người dùng chặn quyền dán
            body = .init(li2Domains: ["your-domain.com"], clipboardStatus: "denied")
        case .optout:                                 // người dùng bỏ qua
            body = .init(li2Domains: ["your-domain.com"], clipboardStatus: "optout")
        }

        Task {
            let res = try await trackOpen(body)
            await route(res)
        }
    }
    ```

    <Tip>
    Dùng `UIPasteControl` (chính cú chạm của người dùng là sự đồng ý, không hiện alert hệ thống) cho production. Việc đọc trực tiếp `UIPasteboard.general.string` sẽ kích hoạt alert dán của iOS.
    </Tip>
  </Tab>

  <Tab title="Android (Kotlin)" icon="android">
    ### 1. Khai báo App Link intent-filter

    Trong `AndroidManifest.xml`:

    ```xml
    <activity android:launchMode="singleTask" ...>
        <intent-filter android:autoVerify="true">
            <action android:name="android.intent.action.VIEW" />
            <category android:name="android.intent.category.DEFAULT" />
            <category android:name="android.intent.category.BROWSABLE" />
            <data android:scheme="https" />
            <data android:host="your-domain.com" />
        </intent-filter>
    </activity>
    ```

    `android:autoVerify="true"` yêu cầu Android xác minh `assetlinks.json` lúc cài đặt. Thiếu nó, Android sẽ hiện hộp chọn ứng dụng thay vì mở thẳng app.

    ### 2. Định nghĩa model & API dùng chung

    Cả luồng immediate lẫn deferred dùng chung một cặp model và một lời gọi:

    ```kotlin
    data class TrackOpenRequest(
        val deepLink: String? = null,
        val li2Domains: List<String>? = null,
        val clipboardStatus: String? = null,   // không dùng trên Android
        val installReferrer: String? = null,
    )

    data class TrackOpenResponse(
        val clickId: String,
        val link: Link?,            // null khi deferred không đối chiếu được
        val matchMethod: String?,
        val missReason: String?,
        val platform: String?,
    ) {
        data class Link(val id: String, val domain: String, val key: String, val url: String)
    }

    interface Li2Api {
        @POST("track/open")
        suspend fun trackOpen(
            @Header("X-Li2-Key") publishableKey: String,   // li2_pk_...
            @Body body: TrackOpenRequest,
        ): TrackOpenResponse
    }

    // baseUrl PHẢI gồm /api/v1/, ví dụ "https://api.li2.ai/api/v1/"
    val api: Li2Api = Retrofit.Builder()
        .baseUrl(BASE_URL)
        .addConverterFactory(GsonConverterFactory.create())
        .build()
        .create(Li2Api::class.java)

    // Điều hướng theo phản hồi: khớp → mở đúng màn hình; trượt → fallback + lý do
    private fun route(res: TrackOpenResponse) {
        res.link?.url?.let { router.open(it) }
            ?: router.showFallbackBanner(res.missReason)
    }
    ```

    ### 3. Xử lý App Link (app đã cài — immediate)

    ```kotlin
    override fun onNewIntent(intent: Intent) {
        super.onNewIntent(intent)
        setIntent(intent)
        handleIntent(intent)
    }

    private fun handleIntent(intent: Intent?) {
        if (intent?.action == Intent.ACTION_VIEW) {
            intent.data?.let { deepLinkViewModel.handleAppLink(it) }
        }
    }
    ```

    `handleAppLink` chỉ gửi `deepLink` (luồng immediate):

    ```kotlin
    fun handleAppLink(uri: Uri) {
        hasReceivedAppLink = true   // chặn luồng deferred ở bước 4
        viewModelScope.launch {
            val res = api.trackOpen(
                BuildConfig.LI2_PUBLISHABLE_KEY,
                TrackOpenRequest(deepLink = uri.toString()),
            )
            route(res)
        }
    }
    ```

    ### 4. Khôi phục deferred qua Google Play Install Referrer

    Trong lần mở đầu tiên, nếu **không** có App Link tới, gọi Install Referrer (chỉ một lần — cờ `firstLaunchRan` lưu trong DataStore):

    ```kotlin
    LaunchedEffect(Unit) {
        delay(250L)
        if (!deepLinkViewModel.hasReceivedAppLink) {
            installReferrerManager.queryOnce()?.let { referrer ->
                deepLinkViewModel.handleInstallReferrer(referrer)
            }
        }
    }
    ```

    `handleInstallReferrer` gửi nguyên chuỗi referrer thô — server tự giải mã tham số `li2_dl=<url-mã-hóa>` mà Li2 đã ghép vào referrer khi chuyển hướng tới Play Store:

    ```kotlin
    fun handleInstallReferrer(referrer: String) {
        viewModelScope.launch {
            val res = api.trackOpen(
                BuildConfig.LI2_PUBLISHABLE_KEY,
                TrackOpenRequest(installReferrer = referrer),
            )
            route(res)
        }
    }
    ```

    <Note>
    **Referrer được Google Play lưu lúc cài, không phụ thuộc cách mở app.** Một hiểu lầm phổ biến là người dùng phải bấm **"Open"** trên Play Store ngay sau khi cài. Thực tế: Play Store ghi nhận chuỗi referrer tại thời điểm cài và giữ lại để truy xuất — bạn lấy được nó ở **lần mở đầu tiên dù app được mở bằng cách nào** (nút *Open*, icon ngoài màn hình chính vài giờ/ngày sau, hay từ thông báo). Không có cửa sổ "mở ngay kẻo mất".

    Hai điều kiện thật sự để có deferred match:
    - Người dùng tới Play Store **qua chính link Li2** (URL mang tham số referrer). Nếu họ tự tìm app trên store thì không có `li2_dl` → trượt với `no_candidate`.
    - App **gọi `InstallReferrerClient` ở lần mở đầu** (như trên). Hãy truy vấn **một lần** rồi lưu kết quả lại, đừng phụ thuộc vào việc gọi lại nhiều lần.
    </Note>

    ### 5. Publishable key trong local.properties

    ```properties
    LI2_PUBLISHABLE_KEY=li2_pk_xxxxxxxxxxxxxxxxxxxx
    ```

    `build.gradle.kts` đọc giá trị này và inject vào `BuildConfig`.

    <Warning>
    **Lỗi phổ biến nhất**: thiếu `LI2_PUBLISHABLE_KEY` trong `local.properties` → `BuildConfig.LI2_PUBLISHABLE_KEY` rỗng → **mọi** lời gọi `/track/open` trả về **401 Unauthenticated**. Thêm key rồi build lại.
    </Warning>

    ### 6. Buộc xác minh App Link

    Sau khi cài hoặc sau khi cập nhật `assetlinks.json`:

    ```bash
    adb shell pm verify-app-links --re-verify your.package.name
    adb shell pm get-app-links your.package.name
    # Phải hiển thị: your-domain.com → verified
    ```

    Nếu thấy `1024` (chưa xác minh), SHA-256 trong dashboard không khớp chứng chỉ ký của APK đang cài.
